# QT-4.8.5-For-Microsoft-Visual-Studio-2015
I was able to get QT 4.8.5 working for Microsoft Visual Studio 2015. Although other versions might not work because of the modified .h and .cpp files.

he 100% compiles all the libraries needed

Ох, синий экран (BSOD) с ошибкой IRQL_NOT_LESS_OR_EQUAL — это неприятно. Обычно он возникает из-за сбоя какого-то драйвера, проблем с оперативной памятью (особенно при сильной нагрузке во время многопоточной компиляции /MP) или из-за конфликта антивируса/сетевого экрана (например, Cloudflare WARP, который виден у вас в PATH).
Не переживайте, весь ваш прогресс компиляции сохранился! Файлы, которые компилятор уже успел собрать до падения системы, лежат на диске. Утилита nmake умная — она проверит даты изменения файлов и продолжит сборку ровно с того места, где всё прервалось.
Чтобы правильно вернуться в процесс, выполните следующие шаги:
## ➡️ Шаг 1. Откройте правильную консоль
После перезагрузки компьютера снова откройте меню «Пуск» и запустите:
VS2015 x86 Native Tools Command Prompt (или Командная строка native-инструментов VS 2015 x86).
## ➡️ Шаг 2. Перейдите в папку проекта
В открывшемся окне введите команду для перехода в каталог библиотеки Qt:

cd C:\keymaster\Roblox2016\Library\Qt

## ➡️ Шаг 3. Восстановите системные пути (Обязательно!)
Так как консоль открылась заново, она забыла путь к компилятору ресурсов rc.exe, который мы прописывали ранее. Обязательно введите команду добавления пути заново, иначе сборка сразу упадет с прошлой ошибкой:

set PATH=%PATH%;C:\Program Files (x86)\Windows Kits\10\bin\10.0.19041.0\x86

## ➡️ Шаг 4. Запустите продолжение сборки
Теперь просто запустите компиляцию:

nmake

Сборщик проверит измененный вами файл ArgList.h в WebKit, пересоберет нужную библиотеку и успешно двинется дальше.
